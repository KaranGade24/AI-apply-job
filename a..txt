# AI-Apply-Job — AI-Powered Job Discovery & Automated Application Platform

## 1. Product Goal

Build a production-grade Node.js application that helps users discover relevant jobs, analyze job listings, decide whether they match the user's profile, personalize application materials, and—when explicitly enabled by the user—automate the application workflow through browser automation.

The system should provide a clean unified dashboard where users can:

* Find jobs from popular job boards such as LinkedIn and Indeed.
* Search and analyze jobs using configurable criteria.
* Automatically discover jobs matching the user's profile.
* Deep-dive into every relevant job listing by default.
* Open the actual job/application page through browser automation.
* Understand the application form dynamically.
* Fill supported application fields using the user's stored profile.
* Generate job-specific cover letters and other application answers with an LLM.
* Ask the user for missing information instead of inventing answers.
* Track every application and automation step.
* Show real-time application status.
* Support multiple applications in an automated queue.
* Provide application history, analytics, failures, and logs.

The system should be designed around **user-controlled automation** rather than blindly submitting applications.

# 8. Deep Dive Should Be the Default

Do NOT make "Deep Dive" a special feature that only works for one job title.

Deep Dive should be part of the normal workflow.

For every relevant discovered job:

```text
Job discovered
      ↓
Open job
      ↓
Analyze actual job page
      ↓
Extract complete job information
      ↓
Find application mechanism
      ↓
Analyze application requirements
      ↓
Determine whether automation is possible
      ↓
Prepare application
```

The system should work generically rather than depending on a hardcoded title.

# 12. Missing Information System

This is extremely important.

The AI must NEVER invent user information.

If an application asks:

```text
Are you legally authorized to work in the United States?
```

and the user has not provided the answer:

```text
AI → Missing user information
```

The application should pause.

Frontend:

```text
Action Required

LinkedIn — Software Engineer

The application asks:

"Are you legally authorized to work in the United States?"

We don't have this information.

[Provide Answer]

[Skip Application]
```

The same system should work for:

* Salary
* Sponsorship
* Notice period
* Relocation
* Work authorization
* Years of experience
* Gender
* Demographic questions
* Security clearance
* Veteran status
* Disability information
* Custom company questions

Do not guess.

# 29. Generic Application Answer Engine

Instead of hardcoding every possible question, create a semantic answer engine.

Input:

```text
Question:
"How many years of experience do you have working with Node.js?"
```

AI maps it to:

```text
userProfile.experience.nodeJs
```

If the value exists:

```text
Return value
```

If unavailable:

```text
REQUEST_USER_INPUT
```

Another example:

```text
"Are you willing to relocate?"

→ userPreferences.relocation
```

Unknown:

```text
"Describe a time when you resolved a production incident."
```

The AI searches:

```text
Experience
Projects
Resume
```

If sufficient information exists, generate an answer.

If not:

```text
ASK_USER
```

# 40. Important Design Principle

Do not build this as:

```text
scrape jobs → click apply → submit
```

Build it as:

```text
DISCOVER
   ↓
UNDERSTAND
   ↓
MATCH
   ↓
DEEP DIVE
   ↓
PLAN
   ↓
PERSONALIZE
   ↓
VALIDATE
   ↓
AUTOMATE
   ↓
VERIFY
   ↓
TRACK
   ↓
ANALYZE
```

The browser is the execution layer.

The LLM is the reasoning/personalization layer.

The database is the source of truth.

The workflow engine is the orchestration layer.

The frontend is the user's control center.

# 42. Primary Product Outcome

The finished application should feel like a **personal AI job-application operating system**.

The user should not have to manually visit every job board, open every listing, analyze every job description, rewrite every cover letter, or repeatedly enter the same information.

Instead:

```text
User Profile
      +
User Preferences
      +
Automation Rules
      ↓
AI-Apply-Job
      ↓
Discover → Analyze → Deep Dive → Personalize → Apply → Track
```

while keeping the user in control whenever information is missing, a site requires manual interaction, or final approval is configured.
